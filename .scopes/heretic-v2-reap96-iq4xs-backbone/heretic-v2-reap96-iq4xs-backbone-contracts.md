## Tensor Classes

The model is divided into three explicit classes:

1. Routed Experts: 96 per layer with top-6 routing. The 129 packed
   gate/up/down expert tensors remain MXFP4 and byte-identical.
2. Shared Expert: one per layer and active for every token. These weights are
   non-routed and participate in llama.cpp's default IQ4_XS mixed policy.
3. Core Backbone: attention, CSA/HCA/mHC projections, Lightning Indexer, token
   embeddings, LM head, and other non-expert linear weights. Eligible tensors
   participate in the same default mixed policy.

Router tensors, `tid2eid`, norms, RoPE, sinks, and other non-quantizable small
tensors are structural non-routed data and remain in their source type. They
must not be treated as ordinary linear weights.

## Quantization Profile

Profile A is the only permitted production profile:

- Base quantization is `IQ4_XS`.
- llama.cpp default mixed-precision protections remain enabled.
- Sensitive attention tensors may be promoted to `Q5_K`.
- `output.weight` and other protected tensors may be promoted to `Q6_K`.
- Shared Expert and Core Backbone weights use llama.cpp's default IQ4_XS mixed
  type selection. No separate Shared Expert override is allowed in Profile A.
- Norm, router, `tid2eid`, and non-quantizable 1D tensors remain unchanged.
- The 129 tensors matching
  `^blk\.[0-9]+\.ffn_(gate|up|down)_exps\.weight$` remain `MXFP4`.
- `--allow-requantize` is required so eligible backbone tensors can change.
- `--pure`, imatrix input, and any Profile B comparison are prohibited.

The output target is:

```text
/data/linux-fast/models/DeepSeek-V4-Flash-0731/
DeepSeek-V4-Flash-0731-HERETIC-v2-REAP96-noMTP-MXFP4exp-IQ4XSbb.gguf
```

Target size is less than `60,000,000,000` bytes. If Profile A misses this
target, record the result and stop. Do not weaken the profile or test `--pure`.

## Direct-I/O Contract

The pinned llama.cpp quantizer must support `--direct-io-input` and
`--direct-io-output`:

- Direct input selects `LLAMA_LOAD_MODE_DIRECT_IO`.
- Direct output writes through aligned `O_DIRECT` staging on the output
  filesystem, synchronizes the file, truncates to the logical GGUF size, and
  atomically renames the staging path to the requested output.
- Dry-run creates no output or staging file.
- A failed quantization never publishes a partial final output.
- After quantization exits zero, the routed-expert finalizer restores all 129
  MXFP4 payloads from the immutable Golden with aligned `O_DIRECT` reads and
  writes. This post-build step is required because sparse stable block drift was
  observed in two rejected quantizer outputs even though the GGUF structure and
  routing payloads were correct.
- Full model input, output, hashing, and payload verification remain direct-I/O
  only on this host.

## Requirement Boundary Notes

This scope quantizes only the immutable K96 Golden. It does not change K96
survivors, hash routing, the Golden, or the K132 deployment. Profile B,
`--pure`, imatrix, alternate quantizations, and quantization-profile A/B are
outside the requirement boundary.

## Runtime Acceptance

Runtime acceptance uses the established dual RTX 5090, 64K, F16 CPU KV,
single-slot llama.cpp baseline. It verifies raw completion, chat, Chinese,
JSON, Python/code, long prefill, and 64K operation while recording load time,
prompt/decode throughput, GPU memory, RAM, swap, and kernel health.

The K96 Golden's known France-prompt first-token quality failure is an upstream
baseline property. The IQ4_XS artifact is evaluated for additional degradation,
repetition, formatting failure, routing errors, or long-context instability;
it is not compared to a Profile B artifact.
